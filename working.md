## 1. Executive Summary & Project Overview

MeatDae is a hyper-localized food-tech application specializing in the sourcing, preparation, logistics, and delivery of fresh (never frozen), non-halal chicken, mutton, and egg products to households in Silchar, Assam. Unlike conventional e-commerce websites, MeatDae implements real-time synchronizations between three active client roles:
1. **The Customer:** browses dynamic listings, adjusts cart sizes, verifies location coordinates on an interactive map, executes online (Razorpay) or cash-on-delivery (COD) payments, tracks the delivery rider on a real-time map, and submits feedback reviews.
2. **The Preparer (Kitchen):** views incoming order flows in a dedicated kitchen queue, accepts orders, handles physical meat preparations (cutting, cleaning, weighing), packs the order, and updates statuses to alert riders.
3. **The Rider:** receives delivery assignments, views route coordinates via MapTiler navigation, updates GPS coordinates, collects cash payments, and requests day-end cash settlements.
4. **The Administrator:** manages inventory availability and pricing tiers, handles staff accounts, tracks settlements, analyzes ledgers, and assigns orders to available riders.

The core design principle is **real-time synchronization**. Rather than reloading pages or running periodic API polls, the entire application relies on Cloud Firestore's real-time snapshot listeners. When a customer places an order, the kitchen dashboard updates instantly. When the kitchen preparer packs the meat, the rider dashboard updates, and the customer receives an email. When the rider starts moving, their physical GPS location updates on the customer's tracking map in real time.

## 2. Technical Stack Deep-Dive

MeatDae is built using a lightweight stack designed for fast mobile rendering.

### 2.1 Frontend Layer
- **HTML5 & Vanilla CSS3:** All structural layout views are written in HTML5. Styling is compiled using Vanilla CSS3, featuring HSL tailored colors, dark gradients, glassmorphism cards, and interactive shadow overlays.
- **Vanilla ES6 Javascript Modules:** No heavy frontend frameworks (such as React, Vue, or Angular) are used. The frontend relies on standard Web APIs (DOM query selectors, fetch promises, geolocation watchers, session storage, and local storage caches) combined with ES module imports.
- **Service Worker API (PWA):** Standard Web Worker configurations cache static assets (HTML, CSS, JS, image assets, webfonts) locally. This allows the application to load instantly on slow networks and show custom offline layouts.
- **Bootstrap (v5.0.0 Bundle):** Used to compile responsive grids, structural containers, typography resets, and standard layout configurations.
- **jQuery (v3.6.0):** Standard library for UI selectors, callbacks, and plugin integrations.
- **Slick Slider (v1.8.1):** Powers the home page promotional banners and client review carousels.
- **Isotope Layout (v3.0.6):** Filters products by category tabs dynamically without reloading.
- **Nice Select (v1.0):** Custom form dropdown select styles.
- **VenoBox (v2.0.4):** Modal overlay and image gallery popup.
- **ExZoom:** Image zooming engine for product details page.
- **Font Awesome (v5.15.4 / v6):** Branded and utility icons.
- **WOW.js & Animate.css:** Micro-animations for page entries.

### 2.2 Backend Layer
- **Node.js Environment:** Powers the static development servers (`server.js`, `customer/server.js`, `staff/server.js`) and compiles backend business logic within Cloud Functions.
- **Firebase Platform:**
  - **Firebase Hosting:** Distributes static portal assets via CDN networks, executing URL rewrite routing schemes.
  - **Firebase Authentication:** Handles customer logins (Email/Password, Google OAuth, Phone OTP validation) and staff credential sessions.
  - **Cloud Firestore:** A document-oriented real-time database managing orders, inventory, settlements, reviews, and logs.
  - **Cloud Functions:** Serverless triggers (Node.js) that execute logic on Firestore document creation/updates.
  - **Firebase Storage:** Houses uploaded profile pictures.

### 2.3 Third-Party API Integrations
- **Razorpay Checkout SDK:** Manages online payments via card, UPI, or net banking. The verification of transactions occurs server-side inside Cloud Functions to ensure payment security.
- **MapTiler Map SDK:** Centered on coordinates for customer order tracking, geocoding address searches, and updating rider location pins on maps.
- **Google Gemini API:** Core engine for the customer-support chatbot.

### 3.2 Order Status Transitions
Orders transition through several well-defined states. Real-time listeners ensure transitions are instantly reflected across customer and staff interfaces.

```
                  ┌───────────────────────┐
                  │   PENDING_APPROVAL    │ ◄─── Order placed by customer (either COD or Razorpay Paid)
                  └──────────┬────────────┘
                             │
                             │ Accepted by Admin or Kitchen Preparer
                             ▼
                  ┌───────────────────────┐
                  │       PREPARING       │ ◄─── Meat is cut, cleaned, and weighed in the kitchen
                  └──────────┬────────────┘
                             │
                             │ Marked as packed by Preparer (isPrepared = true)
                             ▼
                  ┌───────────────────────┐
                  │   READY_FOR_PICKUP    │ ◄─── Order is waiting for rider collection
                  └──────────┬────────────┘
                             │
                             │ Assigned rider marks order as picked up
                             ▼
                  ┌───────────────────────┐
                  │   OUT_FOR_DELIVERY    │ ◄─── Rider travels to customer address; live map starts tracking
                  └──────────┬────────────┘
                             │
                             │ Rider reaches location, delivers order, and collects payment (if COD)
                             ▼
                  ┌───────────────────────┐
                  │       DELIVERED       │ ◄─── Triggers Swiggy-style review popup on customer portal
                  └───────────────────────┘
```
*Note: An order can be marked as `CANCELLED` at any point prior to being marked as `DELIVERED`.*

## 5. Firestore Security Rules Analysis

Defined in `firestore.rules`, the security configurations restrict database access using helper verification methods.

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Core Helper Functions
    function isAuthenticated() {
      return request.auth != null;
    }
    
    // Checks if the authenticated user's UID matches the resource path
    function isOwner(userId) {
      return isAuthenticated() && request.auth.uid == userId;
    }
    
    // Resolves email whitelist or checks user document role
    function isAdmin() {
      return isAuthenticated() && (
        request.auth.token.email in ["aarxslan@gmail.com", "10sahilsarkargg@gmail.com"] ||
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "admin"
      );
    }
    
    // Checks if the user is a registered rider
    function isRider() {
      return isAuthenticated() && (
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "rider"
      );
    }

    // Checks if the user is a kitchen preparer
    function isPreparer() {
      return isAuthenticated() && (
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "preparer"
      );
    }

    // Rules Mapping
    match /users/{userId} {
      allow read: if isOwner(userId) || isAdmin();
      allow write: if isOwner(userId) || isAdmin();
    }
    
    match /inventory/{productId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    
    match /carts/{userId}/{document=**} {
      allow read, write: if isOwner(userId);
    }
    
    match /orders/{orderId} {
      allow read: if isAuthenticated() && (
        resource.data.userId == request.auth.uid ||
        isAdmin() ||
        resource.data.riderId == request.auth.uid ||
        isRider() ||
        isPreparer()
      );
      allow create: if isAuthenticated();
      allow update: if isAuthenticated() && (
        isAdmin() ||
        resource.data.riderId == request.auth.uid ||
        resource.data.userId == request.auth.uid
      );
    }
    
    match /riders/{riderId} {
      allow read: if true;
      allow write: if isOwner(riderId) || isAdmin();
    }
    
    match /reviews/{reviewId} {
      allow read: if true;
      allow create: if isAuthenticated() && request.resource.data.userId == request.auth.uid;
      allow update, delete: if isAdmin();
    }

    match /reviewEmails/{docId} {
      allow create: if isAuthenticated();
      allow read, write: if isAdmin();
    }
    
    match /admin_notifications/{docId} {
      allow read, write: if isAdmin();
    }
    
    match /rider_settlements/{docId} {
      allow create: if isAuthenticated() && isRider();
      allow read, update: if isAdmin();
    }

    match /metadata/order_counter {
      allow read: if isAuthenticated();
      allow write: if isAdmin();
    }

    match /promoCodes/{code} {
      allow read: if true;
      allow write: if isAdmin();
    }
  }
}
```

## 6. Cloud Functions Deep-Dive

### 6.1 `sendNewOrderEmail`
- **Type:** Firestore Trigger.
- **Trigger Condition:** `onCreate` on `/orders/{orderId}`.
- **Purpose:** Constructs an HTML table of ordered items, prices, address info, and transaction totals, and emails it to the store admin.
- **SMTP Transport Configuration:**
  ```javascript
  const transporter = nodemailer.createTransport({
    service: "gmail",
    auth: {
      user: process.env.GMAIL_USER,
      pass: process.env.GMAIL_APP_PASSWORD
    }
  });
  ```
- **Email Subject Format:** `New Order Received: {orderId}`
- **Destination:** Evaluates `process.env.ADMIN_EMAIL`, falling back to `contact.meatdae@gmail.com`.

### 6.2 `sendStatusUpdateEmail`
- **Type:** Firestore Trigger.
- **Trigger Condition:** `onUpdate` on `/orders/{orderId}`.
- **Purpose:** Monitors changes to the `status` field. If the status changes to `PREPARING`, `OUT_FOR_DELIVERY`, `DELIVERED`, or `CANCELLED`, it drafts a transactional email and sends it to the customer.
- **Logic:**
  ```javascript
  const before = change.before.data();
  const after = change.after.data();
  if (before.status === after.status) return null;
  
  const email = after.customerEmail || after.userEmail;
  if (!email) return null;
  ```

### 6.3 `sendReviewEmail`
- **Type:** Firestore Trigger.
- **Trigger Condition:** `onCreate` on `/reviewEmails/{docId}`.
- **Purpose:** Notifies store owners whenever a user submits a review.
- **Logic:** Renders a star rating layout (e.g. `★` characters mapped to the rating score) and lists user comments, names, and contact details.

### 6.4 `askGeminiBot`
- **Type:** HTTPS Trigger (onRequest).
- **Endpoint Route:** `/askGeminiBot`
- **Purpose:** Handles conversational responses for the AI support assistant.
- **CORS Handling:**
  ```javascript
  res.set("Access-Control-Allow-Origin", "*");
  res.set("Access-Control-Allow-Methods", "POST, OPTIONS");
  res.set("Access-Control-Allow-Headers", "Content-Type");
  if (req.method === "OPTIONS") { res.status(204).send(""); return; }
  ```
- **Gemini API Integration:** Sends a POST request to `https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent?key={key}` containing the system prompt, store details, and conversation context.

### 6.5 `placeOrderSecure`
- **Type:** HTTPS Callable (onCall).
- **Purpose:** Validates cart contents, calculates delivery charges, verifies payment statuses, and registers orders securely on the server.
- **Key Implementation Logic:**
  - Validates user sessions.
  - Queries available inventory to verify that items in the cart are in stock and that their prices match database records.
  - Computes delivery charges by matching address keywords against a list of locations and applying pincode fallbacks.
  - Checks if the subtotal is greater than ₹350 to qualify for free delivery.
  - Validates coupon codes and calculates discounts.
  - If payment is via Razorpay, it makes a secure server-to-server call to verify the payment ID status before registering the order.
  - Runs a Firestore transaction to increment the sequential order counter and writes the order document.

### 6.6 `createAdminNotification`
- **Type:** Firestore Trigger.
- **Trigger Condition:** `onCreate` on `/orders/{orderId}`.
- **Purpose:** Creates a notification document in the `admin_notifications` collection to alert admins of incoming orders.

## 22. Geolocation & Real-Time Tracking Logic

The real-time tracking system is built on two endpoints:
1. **Rider Client GPS Polling (`staff/js/rider.js`):**
   - The rider's browser calls `navigator.geolocation.watchPosition` with `enableHighAccuracy: true` and a `maximumAge: 0`.
   - The callback writes a new `GeoPoint` containing the current latitude and longitude to the `/riders/{riderId}` collection and updates the rider's user profile document in Firestore:
     ```javascript
     const riderLocation = new firebase.firestore.GeoPoint(latitude, longitude);
     await updateDoc(doc(db, "riders", riderId), {
       location: riderLocation,
       lastUpdated: serverTimestamp()
     });
     ```

2. **Customer Tracker listener (`customer/js/order_track.js`):**
   - Centered on the customer's delivery coordinates, it initiates a real-time snapshot listener on the `/riders/{assignedRiderId}` document.
   - On each coordinate change, it computes the distance using the **Haversine Formula**:

## 23. secure Order Processing & validation Calculations

All calculations occur server-side inside the `placeOrderSecure` Cloud Function to prevent tampering with prices or inventory.

### 23.1 Delivery Fee Keyword Surcharges
The function analyzes address text strings for keyword matches to calculate fees, using pincodes as fallbacks:

- **₹15 Keyword Zones:** `meherpur`, `rongpur`, `tarapur`, `itkola`, `malugram`, `national highway` / `national hw` (matches `nh road` or `nh bypass`), `2nd link road`.
- **₹17 Keyword Zones:** `bagatpur`, `kathal road`, `ghaniwala`, `peshkar road`, `maruti suzuki`.
- **₹18 Keyword Zones:** `masimpur`, `tupkhana`.
- **₹20 Keyword Zones:** `suncity`, `green hills`, `valley hospital`, `beltola`, `silcoorie`, `ghungoor`, `kabuganj`, `shivalik park`.
- **₹25 Keyword Zones:** `udharbond`, `srikona`.
- **Surcharges:** Adds a ₹7 surcharge if the order contains 200g items or leg piece solo packs.
- **Free Delivery Minimum Threshold:** Waives delivery fees for orders over ₹350.
- **Online Payment Transaction Surcharge:** Adds a ₹11 processing fee for Razorpay orders.

### 23.2 Hardcoded Coupon Codes
The system supports hardcoded coupon codes, which are validated in `placeOrderSecure` to ensure consistent discounts:

- **MEAT10:** Offers a 10% discount on order subtotals.
- **AQUALITY, PLUSQUALITY, APLUS, HAPPY, THANKS, SAHIL:** Offers a 2% discount on order subtotals.
- **Minimum Discount:** Stretches the discount to a minimum of ₹4 if the calculated percentage discount is less than ₹4.

### 23.3 Razorpay Payment Verification & Security Config
Online payments are verified server-side inside the `placeOrderSecure` Cloud Function using the private Razorpay Key Secret:
- **Key Storage:** The public **Key ID** (`rzp_live_TG5jXz4jsRuo3B`) is exposed on the client-side to load the checkout widget. The private **Key Secret** (`[REDACTED]`) is securely loaded into the Cloud Functions environment variables via a gitignored `functions/.env` file.
- **Payment Verification:** For all `Online (Razorpay)` orders, the backend makes an authenticated API request to `https://api.razorpay.com/v1/payments/{paymentId}` to verify:
  1. The transaction status is either `captured` or `authorized`.
  2. The actual paid amount (converted from paise) matches the server-calculated order total within a ₹5 rounding tolerance.
- If verification fails or payment ID is missing, the transaction is rejected, and order registration in Firestore is aborted.

## 24. Known Risks, Security Audit Checklist & Recommendations

1. **Hardcoded Whitelists:** The Admin email whitelist is hardcoded in the Firestore rules, meaning admin access cannot be changed without redeploying the rules.
2. **Missing Input Sanitization:** User inputs (e.g. addresses, reviews, notes) are written directly to Firestore, posing cross-site scripting (XSS) risks.
3. **Exposed API Keys:** The MapTiler API Key and Razorpay Key ID are hardcoded in client-side JS files. *Note: Razorpay checkout vulnerability has been resolved by implementing server-side payment validation using the private Key Secret in Cloud Functions environment variables.*
4. **Duplicate Coupon Logic:** Coupon discount values are hardcoded in multiple files (checkout, payment, and cloud functions), which could lead to inconsistencies.
5. **No Cloud Function Rate Limiting:** The `askGeminiBot` endpoint lacks rate limiting, leaving it open to brute-force query attacks.
6. **No Automated Testing:** The project lacks automated test suites, making updates prone to regression issues.
7. **Legacy SDK Libraries:** The frontend imports the Firebase v9.6.1 compat-layer SDK via CDNs, which prevents tree-shaking and results in larger bundle sizes.
8. **Dev Logger Security:** The debug server running on port 9999 is active in production code, which could expose debug logs to unauthorized users.

- **Logic Detail:** Triggers on `/orders/{orderId}` updates. Checks if the `status` string field has modified. If changed, resolves customer email address and sends a customized email showing the new state (PREPARING, OUT_FOR_DELIVERY, etc.).
- **Side Effects:** Writes data records, triggers email notifications, and updates coordinates.

### Function: `sendReviewEmail`
- **Scope:** `functions/index.js` backend trigger.
- **Logic Detail:** Triggers on `/reviewEmails/{docId}` creation. Extracts star rating integers, compiles customer feedback comments, and sends email notifications to administrators.
- **Side Effects:** Writes data records, triggers email notifications, and updates coordinates.

### Function: `askGeminiBot`
- **Scope:** `functions/index.js` backend trigger.
- **Logic Detail:** HTTPS onRequest POST endpoint. CORS-enabled. Validates API keys. Injects store operating parameters and product details, sending user queries to the Gemini-1.5-Flash model.
- **Side Effects:** Writes data records, triggers email notifications, and updates coordinates.

### Function: `placeOrderSecure`
- **Scope:** `functions/index.js` backend trigger.
- **Logic Detail:** HTTPS callable function. Authenticates sessions, calculates prices, delivery fees, and promo codes. Verifies Razorpay payments and records orders inside transactions.
- **Side Effects:** Writes data records, triggers email notifications, and updates coordinates.

### Function: `createAdminNotification`
- **Scope:** `functions/index.js` backend trigger.
- **Logic Detail:** Firestore trigger creating dashboard logs under `/admin_notifications` on order placement.
- **Side Effects:** Writes data records, triggers email notifications, and updates coordinates.
